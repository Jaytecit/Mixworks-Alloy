# User-facing controls and command obligations

The lexical [control sites](inventory/control-sites.csv) and [CLI options](inventory/cli-options.csv) preserve actual source locations, text/handler/declaration sites and rule mappings. One line can declare several controls; one control can occur at many sites. Do **not** treat the lexical site count as a count of distinct verified controls. This semantic inventory covers families and explicit dynamic expansion below. At audit execution make a per-instance trace ledger under the run root; U01 cannot PASS until every constructed shipping instance has a row, including newly exposed popups/submenus. Unexplained declaration-only/handler-only/unreachable sites are suspects requiring investigation, not assumed working features.

Each trace row requires stable semantic name (e.g. `transition.band[2].gap`), source declaration/construction, input route/menu ID/shortcut/gesture/MIDI action, admission conditions, target identity, handler/model/engine, visible value/unit/range/reset, Undo/persistence/output effect, normal/invalid/cancel/recovery case, evidence and status. Navigation/presentation controls explicitly record `no musical mutation`; disabled placeholders record reason/no side effect. Native route coverage and bridge/model routes are separate fields.

## Exhaustive expansions and discovery checks

Enumerate actual menu items recursively including submenus built by addBarMenus/displayMenu, native JUCE settings children and dynamically generated source/plugin/preset/take/profile items. Their finite domains must be listed by stable target IDs in evidence; arbitrary large source lists use empty/one/many/missing/stale partitions plus every command kind, not every song as a separate test. Expand four lanes, four bands, three alternatives, nine cues, eight desk pots and every `midiActions()` item. Enumerate constructed recording-mode selector values from source; do not infer features from old prose calling it Latch.

For gesture sites, record hit region and focus, actual mouse down/drag/up/key sequence, snapping/default/cancel path, target after selection/reorder, enabled states and result. For factories, resolve every caller and target class; for declarations without handler/consumer, record a suspect disconnected control and inspect runtime before confirming. The CSV includes declarations and handlers expressly to expose these gaps; a generated matching row is not proof that the control works. Any undocumented control discovered during execution adds a ledger row/rule mapping before U01 passes.

CLI options are occurrence records: test selectors and script argparse options are not all main-application flags. Inspect owning parser and Main dispatch before executing. `--recover-imports` and analysis migration/library preparation can mutate persistent data and must never run against production as an audit convenience. Experimental Auftakt/probe commands remain provenance/research scope unless a current user-facing route is demonstrated.
