# Visual show acceptance

Added 1 November 2026. These extend the existing rules; none is currently accepted.
Resource/frame-rate qualification is deferred under the current user instruction.
Inherit [the rule contract](../RULES.md). Primary source owners are
VisualArrangement, VisualScenes, SceneLane, Model persistence and the repository
visual worker/compositor/presenter. Use isolated native fixtures and actual UI
captures, plus independent interval arithmetic and saved-file inspection. Retain
exact candidate/source hashes, commands, results and captures. All three rules are
P1; test absence or an unavailable output method leaves acceptance open.

### MW-V01 Complete and deliberate automatic visual arrangements

UA01/UA02. A 44-track arrangement covers zero through the final audible music end.
Independently inspect ordered intervals, every handover, short/overlapping tracks,
image eligibility and whole-show scene/transition variety. Cuts require an explicit
visible reason/choice. Save/reopen retains the complete schedule. Inspect actual
beginning/middle/end scene pixels separately from schedule correctness. No frame-rate
measurement is needed for functional acceptance.

### MW-V02 Manual scenes, images and transitions have clear ownership

Scene library selection/preview, add/move/trim/delete, image set/clear and transition
edits affect the named scene or project, with predictable Undo and saved identity.
Missing/unsupported media and unavailable scenes give actionable feedback without
silently altering music. Verify native gestures and reopened scene/transition values;
do not imply video input or audiovisual export is offered.

### MW-V03 Preview and output lifecycle preserve the music workflow

Preview/output open, close, pause, seek, scene handover, worker failure and reopen
show the intended current musical moment and recover or report failure clearly.
Check actual native child-window pixels and cleanup, without controlling another
session or display configuration. Music/session state remains intact. Physical
display, long-running resource limits and frame pacing require later separate evidence.
